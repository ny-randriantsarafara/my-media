# CI/CD — plan d'implémentation

> Spec : `docs/superpowers/specs/2026-10-11-cicd-design.md`. Étapes cochées au fil de l'exécution.

**Objectif :** CI requise sur `main`, previews par PR, staging automatique et production promue manuellement, sur le socle `vps-services`.

**Contraintes :**

- Actions épinglées par SHA complet, permissions minimales, `persist-credentials: false`.
- Aucun secret dans Git ni dans les journaux. Clés et mots de passe générés localement, envoyés aux secrets GitHub, copie lisible hors Git en `0600`.
- Changements du socle dans `vps-services`, par PR de ce dépôt. Changements produit dans `my-media`.
- Branches `feat/`, `fix/` ou `chore/`. Commits Conventional Commits en anglais.

## Étape 1 — CI de `my-media` (branche `chore/ci`)

- [x] `scripts/ci/write-env.sh` : `.env` de CI dérivé de `.env.example`, chaque `change-me` remplacé par une valeur aléatoire.
- [x] `.github/workflows/ci.yml` : jobs `Checks` et `Integration`.
- [x] `AGENTS.md` : règles du dépôt (PR obligatoire, checks, commandes locales, déploiement).
- [x] Spec et plan commités dans la même PR.
- [x] Push, PR, CI verte, fusion.
- [x] Dépôt public ; ruleset `main` (PR, checks `Checks` et `Integration`, pas de force push ni de suppression, aucun contournement).
