# CI/CD — plan d'implémentation

> Spec : `docs/superpowers/specs/2026-10-11-cicd-design.md`. Étapes cochées au fil de l'exécution.

**Objectif :** CI requise sur `main`, previews par PR, staging automatique et production promue manuellement, sur le socle `vps-services`.

**Contraintes :**

- Actions épinglées par SHA complet, permissions minimales, `persist-credentials: false`.
- Aucun secret dans Git ni dans les journaux. Clés et mots de passe générés localement, envoyés aux secrets GitHub, copie lisible hors Git en `0600`.
- Changements du socle dans `vps-services`, par PR de ce dépôt. Changements produit dans `my-media`.
- Branches `feat/`, `fix/` ou `chore/`. Commits Conventional Commits en anglais.

## Étape 1 — CI de `my-media` (branche `chore/ci`)

- [ ] `scripts/ci/write-env.sh` : `.env` de CI dérivé de `.env.example`, chaque `change-me` remplacé par une valeur aléatoire.
- [ ] `.github/workflows/ci.yml` : jobs `Checks` et `Integration`.
- [ ] `AGENTS.md` : règles du dépôt (PR obligatoire, checks, commandes locales, déploiement).
- [ ] Spec et plan commités dans la même PR.
- [ ] Push, PR, CI verte, fusion.
- [ ] Dépôt public ; ruleset `main` (PR, checks `Checks` et `Integration`, pas de force push ni de suppression, aucun contournement).

## Étape 2 — Socle (`vps-services`, branche `feat/multi-route-instances`)

- [ ] `compose.py` : hostname principal ou `<préfixe>.<label>.<domaine>`, unique par instance ; helper `instance_hostnames`.
- [ ] `runtime.py` : sondes sur toutes les routes de l'instance.
- [ ] Tests : routes secondaires acceptées, préfixe invalide, hostname d'une autre instance, doublon, sondes.
- [ ] Docs : APP-CONTRACT (routes), CICD (automatisation approuvée pour `my-media`), CHANGELOG 1.1.0, `galaxy.yml` 1.1.0, spec courte.
- [ ] Inventaire : `vps_domain`, comptes `my-media-nonprod` et `my-media-prod` (clés générées pour l'occasion).
- [ ] `make check` vert ; PR ; CI verte ; fusion.
- [ ] DNS `*.apps` A/AAAA (skill cloudflare-access) ; résolution vérifiée.
- [ ] `make plan` puis `make platform TARGET=vps-d9d9aca9` ; `vpsctl status` vérifié.

## Étape 3 — Livraison sur le socle (`my-media`, branche `feat/platform-delivery`)

- [ ] `cms/provision` : jeu de démo (`DEMO_CONTENT=true`), chargé seulement si aucun article n'existe ; tests unitaires.
- [ ] `site/src/middleware.ts` : en-têtes de sécurité ; test unitaire.
- [ ] `deploy/` : `compose.yml.j2`, playbook, environnements, inventaire, `known_hosts`, `requirements.yml` (SHA de `vps-services`), `requirements.txt` à hashes, `smoke.sh`.
- [ ] Workflows `images.yml`, `deploy.yml`, `preview.yml` ; staging dans `ci.yml`.
- [ ] Environnement GitHub `nonprod`, secrets d'environnement et secrets Dependabot ; copie locale des valeurs.
- [ ] Suppression de `ops/` (sauf `smoke.sh`, déplacé), de `compose.production` et de la doc d'exploitation obsolète ; mise à jour de la doc.
- [ ] Simulation locale du Compose rendu avec les mêmes plafonds (démarrage de Directus sous 0,2 vCPU).
- [ ] PR : CI verte, preview `my-media-pr-<n>` en ligne, démo visible, smoke vert.
- [ ] Package GHCR public.
- [ ] Fusion : staging en ligne, smoke vert ; fermeture de la PR : preview détruite.

## Étape 4 — Production (`my-media`, branche `feat/production-delivery`)

- [ ] `.github/workflows/production.yml`.
- [ ] Environnement `production` : branche `main`, reviewer requis, secrets de prod ; copie locale des valeurs.
- [ ] PR, CI, fusion, staging.
- [ ] Run « Deploy production » approuvé : `my-media-prod` en ligne, smoke vert.
- [ ] `vpsctl status` : prod, staging, aucune preview restante.

## Vérification finale

- [ ] URL publiques des trois environnements en HTTPS.
- [ ] Une PR de test montre preview, check requis et destruction à la fermeture.
- [ ] Documentation à jour dans les deux dépôts ; pointeurs de sous-modules du hub mis à jour.
